# Frappe / ERPNext on Coolify

A multi-site Frappe v16 bench (ERPNext, HRMS, CRM) packaged for the **Docker Compose** build pack in [Coolify](https://coolify.io), for a self-hosted server exposed through a Cloudflare Tunnel.

Based on the official [frappe/frappe_docker](https://github.com/frappe/frappe_docker) layered image and compose setup.

## Project layout

| File | Purpose |
| --- | --- |
| `apps.json` | Apps baked into the image (edit to add/remove apps). |
| `Dockerfile` | Builds the bench from `frappe/build:version-16` and `frappe/base:version-16`. |
| `docker-compose.yml` | All services: frontend (nginx), backend (gunicorn), websocket, workers, scheduler, MariaDB, Redis. |
| `scripts/configure.sh` | Writes DB/Redis settings to `common_site_config.json` (runs once per deploy). |
| `scripts/create-sites.sh` | Creates missing sites from `SITES`, installs missing apps, migrates (runs once per deploy). |
| `scripts/entrypoint.sh` | Links the image's built assets into the `sites` volume on container start. |
| `scripts/start.sh` | Starts gunicorn. |
| `.env.example` | All environment variables you can set in Coolify. |

## How requests flow

```
Browser ──https──> Cloudflare ──tunnel──> cloudflared ──http:80──> Coolify proxy (Traefik)
        ──> frontend:8080 (nginx) ──> backend:8000 / websocket:9000
```

nginx selects the Frappe site from the `Host` header, so **each site name must be exactly its domain** (e.g. `erp.example.com`).

## Deploy on Coolify

1. Push this repository to your git provider.
2. In Coolify: **New Resource → Git repository → Build Pack: Docker Compose**, compose file `docker-compose.yml`.
3. **Environment Variables** — at minimum:

   ```dotenv
   SITES=erp.example.com,hr.example.com
   ```

   `SERVICE_PASSWORD_DB` (MariaDB root) and `SERVICE_PASSWORD_ADMIN` (Frappe `Administrator`) are generated by Coolify. See `.env.example` for the optional variables.
4. **Domains** — set them only on the `frontend` service, one per site, with the container port `8080`:

   ```
   http://erp.example.com:8080,http://hr.example.com:8080
   ```

   Use `http://` because Cloudflare terminates TLS. With `https://` Coolify tries Let's Encrypt and redirects HTTP to HTTPS, which loops when the tunnel connects on port 80.
5. **Cloudflare Tunnel** — add a public hostname for each site (or a wildcard `*.example.com`) pointing to `http://localhost:80` (Coolify's proxy).
6. **Deploy.** The first build takes a while (it clones and builds all apps). Afterwards, follow the `create-sites` container logs; each new site takes a few minutes.
7. Open `https://erp.example.com` and log in as `Administrator` with the value of `SERVICE_PASSWORD_ADMIN`.

## Multiple sites (one bench)

All sites share the same apps and code but have separate databases.

- **Add a site:** append its domain to `SITES`, add `http://<domain>:8080` to the frontend domains, add it to the Cloudflare tunnel, redeploy.
- **Choose apps for new sites:** `INSTALL_APPS=erpnext,hrms` (default: every app in `apps.json`).
- **Remove a site:** remove it from `SITES` and drop it manually (see below). Removing it from `SITES` alone does not delete it.

## Multiple benches

Use a separate bench when sites need different apps or versions.

1. Create another Coolify resource from this repo (typically another branch with its own `apps.json`).
2. Set a unique `BENCH_NAME` per bench (e.g. `main`, `client2`) so their built images do not overwrite each other on the same server.
3. Give each bench its own domains. A domain must point to only one bench.

Each bench gets its own MariaDB, Redis and volumes.

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `SITES` | required | Comma separated site domains. |
| `BENCH_NAME` | `main` | Image name suffix; unique per bench on one server. |
| `INSTALL_APPS` | all apps | Comma separated apps installed on new sites. |
| `SITE_PROTOCOL` | `https` | Used for each site's `host_name` (public URL in emails, links). |
| `AUTO_MIGRATE` | `true` | Run `bench migrate` on existing sites every deploy. |
| `GUNICORN_WORKERS` | `2` | Gunicorn worker processes. |
| `GUNICORN_THREADS` | `4` | Threads per worker. |
| `GUNICORN_TIMEOUT` | `120` | Request timeout (seconds). |
| `PROXY_READ_TIMEOUT` | `120` | nginx proxy read timeout. |
| `CLIENT_MAX_BODY_SIZE` | `50m` | Max upload size. |

## Updating apps

Redeploy in Coolify. Branches in `apps.json` are re-cloned when the build cache is invalidated. To force a fresh clone, change `apps.json` or enable **Disable build cache** for one deploy. With `AUTO_MIGRATE=true`, sites are migrated automatically.

To add an app, add it to `apps.json` and redeploy. `create-sites.sh` installs it on every site listed in `SITES` (unless `INSTALL_APPS` excludes it).

## Common operations

Run these from Coolify's **Terminal** on the `backend` container (working directory is the bench):

```bash
bench --site erp.example.com backup --with-files
bench --site erp.example.com migrate
bench --site erp.example.com set-admin-password 'new-password'
bench --site erp.example.com console
bench drop-site erp.example.com --db-root-password '<value of SERVICE_PASSWORD_DB>'
```

Backups are written to `sites/<site>/private/backups` inside the `sites` volume.

## Troubleshooting

- **`The key must start with a letter or underscore...`** — Coolify reads every `environment:` value starting with `$` as a variable name. Do not add values like `$$host` or inline shell scripts to `docker-compose.yml`; put scripts in `scripts/`.
- **404 / "site does not exist"** — the domain in the browser does not match a site name in `SITES`, or `create-sites` has not finished. Check its logs.
- **Redirect loop** — the Coolify domain uses `https://` while the tunnel points at port 80. Use `http://` domains.
- **Old CSS/JS after an update** — hard-refresh the browser; assets come from the image and update on every rebuild.
- **`create-sites` failed midway** — fix the cause, drop the half-created site with `bench drop-site`, and redeploy.
